# 工作流改进建议书（2026-10-30）

> 适用仓库：`dy-live-ecommerce-editor`（抖音带货直播切片自动化流水线）
> 基线版本：`constraints v1.7` / QC 30+ 断言 / 四段式漏斗（hook·fabric·fit·styling）
> 来源：〈女装达人直播切片提示词·最终整合版〉审查结论（见 `docs/prompt_review_2026-10-30.md`）+ 本仓库实际代码能力
> 用法：按章节直接取用；每项都标了"落在哪个文件""触发条件""怎么验收"，不需要再二次翻译

---

## 阅读指引

- 每条建议统一四段式：**用途 → 收益 → 触发条件/典型场景 → 实施落点与验收**
- 优先级只在最后一张 Roadmap 表里定，正文按主题分类，便于按需跳读
- 标 ⚠️ 的条目会**改变成片形态或 QC 口径**，需先决策再实施

## 一、内容结构类（不改架构，只调比例与顺序）

这一类的共同特点：**现有产物里已经有全部信息**（`plan.json` 的 category/dur/sticker、`dialogue_script.json` 的语句），只是缺"比例约束"。因此几乎都是加断言，风险最低。

### 1.1 参数类内容占比上限（fabric ≤ 25%）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 控制面料/做工/参数类镜头在成片里的时长占比，把时间让给场景、搭配、上身效果 |
| **收益** | 直接改善完播：观众看的是"我什么时候穿、穿上什么样"，不是"多少支纱"。当前 `funnel.fabric: 8–20s`，在 46–60s 成片里折算 13–43%，**上限偏松**，实际成片常出现"半片都在讲面料" |
| **触发条件** | 每个成片必检；类目稀薄素材（fabric 候选不足）自动降级为 WARN，不拦交付 |
| **落点** | `contracts/constraints.yaml`：`funnel.fabric.max` 20 → 12；`src/qc/qc_auditor.py` 新增断言「fabric 时长占比 ≤ 0.25」 |
| **验收** | 3 条历史成片回跑：占比实测值落入 15–25%；无一条因该断言失败 |

### 1.2 主题款明确检查（前 5 秒必须点明"这次讲的是哪一件"）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 防止观众把主题款误认成内搭/裤子/鞋子——达人开场通常穿着完整，只听到"显瘦/好看"会误判 |
| **收益** | 减少"点进来发现不是想买的那件"的跳出；对多品类混播素材尤其关键（本仓库已有品类防错配选段，但那是"选段层面"，这是"开场层面"） |
| **触发条件** | 每个成片必检；`spec.options.skip_topic_anchor=true` 时跳过（如纯氛围向切片） |
| **落点** | `src/qc/qc_auditor.py` 新增断言：前 5s 的 ASR 文本须命中「这件/这条/这双/这个/这款 + 核心词」或直接命中 `product.core_words` |
| **验收** | 现有 3 条成片不误报（WARN 起步）；补 2 条反例 fixture（开场只讲"显瘦"不提款）必须命中 |

### 1.3 贵材质强调 ≥ 1 处

| 项 | 内容 |
| :--- | :--- |
| **用途** | 羊绒/羊毛/桑蚕丝/真丝等贵材质至少要有一句达人原声强调，让价格有支撑 |
| **收益** | 提升"贵得有理"的信任感；这是当前 `highlight_keywords` 只用于字幕高亮、**没有反向校验**的空白 |
| **触发条件** | `spec.options.highlight_keywords` 含贵材质词时启用；纯棉/化纤类商品不触发 |
| **落点** | QC 断言：贵材质词在成片 ASR（`final_asr_segments`）中出现 ≥ 1 次；素材确实没提则 WARN |
| **验收** | 针织衫素材（台词 0 次提及桑蚕丝）应正确报 WARN，而不是静默通过 |

### 1.4 搭配镜头数上限（2–5 种）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 防止成片变成"搭配大赏"：搭配种类太多会稀释主商品 |
| **收益** | 保持主款曝光密度；当前 `styling` 配额 15–30s 但无"几种搭配"的计数约束 |
| **触发条件** | `styling` 类目分镜数 > 5 时告警 |
| **落点** | `src/tools/build_plan.py`（选段时限制 styling 块数）+ QC 断言「styling 分镜数 ∈ [2,5]」 |
| **验收** | 多搭配素材回跑，styling 块数被限到 5 以内且总时长仍在区间内 |

## 二、选段质量类（提升"选得准"，需小改选段算法）

### 2.1 句子级赘述去重

| 项 | 内容 |
| :--- | :--- |
| **用途** | 删掉"黑色一套，黑色一套我给大家穿了看一下……"这类同一句反复铺垫，只留一条 |
| **收益** | 直接减少观感拖沓；当前只有**字符级叠词去重**（"真的真的"→"真的"），跨句重复完全没处理 |
| **触发条件** | 同一 block 内相邻段文本相似度 ≥ 0.8（difflib.SequenceMatcher），保留情绪更强/更完整的一条 |
| **落点** | `src/tools/build_plan.py` 块内后处理（`build_blocks` 之后、`_trim_block_to_duration` 之前），必须保持句子边界语义 |
| **验收** | 新增单测：「黑色一套×2」只留一条；「件件都好看」这类实义叠词不被误删 |

### 2.2 Hook 卖点优先级权重

| 项 | 内容 |
| :--- | :--- |
| **用途** | 前 5 秒优先选"显白/显瘦/小个子适配/反差明显"，而不是"好看/气质"这类泛词 |
| **收益** | 提高首屏留人率；当前 `HOOK_KEYWORDS` 是 40+ 词平铺，`_segment_score` 只数命中个数，**泛词和强卖点等权** |
| **触发条件** | hook 类目选段时恒生效 |
| **落点** | `build_plan.HOOK_KEYWORDS` 改为「词 → 权重」字典（强卖点 3.0 / 中等 1.5 / 泛词 1.0），`_segment_score` 按权重累加 |
| **验收** | 同一素材 hook 选段不劣化（对比现有成片的前 5 秒），且强卖点段落优先 |

### 2.3 情绪瞬间识别（低成本近似）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 优先保留"试穿惊喜、脱口而出感叹"的片段 |
| **收益** | 真实情绪是高完播的最强信号；当前无任何情绪信号 |
| **触发条件** | 该 block 的音频 RMS 峰值高于全素材 P80，或文本含感叹标记（"太…了/绝了/我的天"） |
| **落点** | 选段前对候选 block 的音频做一次 RMS 峰值统计（可复用 `ffmpeg astats`），作为 `_segment_score` 加分项（+2~3） |
| **验收** | 抽样 10 条成片，前 10 秒含感叹句的比例上升；不得引入"喊麦式"噪声片段（黑名单兜底） |

### 2.4 动态优先（运动能量评分）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 走动/转身/拉扯衣服的画面优先于坐着纯讲 |
| **收益** | 动态画面天然更抓眼，且能展示版型；当前选段完全是"文本驱动"，画面信息未参与 |
| **触发条件** | 同分候选之间用运动能量打破平局（不是主排序，避免误杀干货段落） |
| **落点** | 抽帧算帧差均值（OpenCV `absdiff` + 均值），写入 block 的 `motion_score`；`_segment_score` 加权 +1~2 |
| **验收** | 对比 5 条成片的"静态讲解段占比"下降；干货段（面料细节特写）不被误伤 |

### 2.5 多色处理（分两阶段）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 支持多色商品：建颜色清单、偏好色多展示、颜色切换时画面必须跟上 |
| **收益** | 女装高频场景；**这是当前仓库最大空白**。且偏好色占比是可量化硬规则，最适合进 QC |
| **触发条件（阶段一）** | `spec.product.colors` 非空时启用（2 色 60–70% / 3 色 45–55% / 4 色 40–50% / >4 色 ≥40%） |
| **触发条件（阶段二）** | 出现颜色引导语（"再看/另外/这是×色/帮大家试一下×色"）时校验下一镜 |
| **落点** | 阶段一：spec 新增 `product.colors[]` + `options.color_preference`；对分镜做颜色标注（人体区域内颜色直方图或 CLIP 零样本），QC 出「偏好色占比」断言（WARN 起步）<br>阶段二：`build_plan` 记住"引导语所在 block"与"下一 block 颜色"，不一致时降权/换段 |
| **验收** | 阶段一：双色素材（奶白/奶咖）偏好色占比落在 60–70%±5%；阶段二：构造"说黄色→接白色"的反例必须被拦 |

> 说明：只按"达人上身"计入时长，手持/助播拿着不算——这条会让颜色标注需要区分"上身区域 vs 手持区域"，建议阶段一只统计人体 bbox 内的主色，阶段二再细化。

### 2.6 遮挡优先级（多色讲解时）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 单独讲某色时优先无遮挡片段（毛衣别被马甲/大衣盖住，裤子别被长外套挡） |
| **收益** | 观众能看清商品本体，减少"看不清"的差评 |
| **触发条件** | 颜色单独讲解的 block（非搭配展示环节） |
| **落点** | 复用 `detect_garment_match` 的躯干区域 + 衣着一致性分数，低于阈值的 block 降权 |
| **验收** | 有外套遮挡的素材中，纯色讲解段优先选到无遮挡片段 |

## 三、画面与音频呈现类

### 3.1 视频端构图硬指标（头顶距顶 ≤ 17%）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 达人画面偏小时等比放大，让观众看清衣服与整体 |
| **收益** | 当前**只有封面**有构图约束（`head_top_min_ratio: 0.13`），视频分镜端完全没有——成片常出现"人很小、半屏空景" |
| **触发条件** | 抽样帧检测到头顶距离 > 画面高 17% 时触发该分镜放大 |
| **落点** | 复用 `extract_cover_candidates.normalize_subject_framing` 的几何思路（等比 + 底边固定 + 左右对称裁切 + 全幅覆盖不留黑边），改为作用于每个 clip 的抽帧评估 → 写入 `plan.clips[i].framing_scale` → `build_clip_filter` 消费 |
| **验收** | 成片抽帧复测：头顶距顶 ≤ 17% 且不降清晰度（沿用 `post_scale_sharpness ≥ 200` 的既有门禁） |

### 3.2 语速调节开关（1.0 / 1.1 / 1.2）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 整体语速提到原素材 1.1–1.2 倍，节奏更紧 |
| **收益** | 完播率提升；但**这是全链最危险的一项改动**——ASS 时间轴、消音窗口、xfade offset、V1 字幕-原声一致性、时长折算全部要按倍率换算 |
| **触发条件** | `constraints.time_stretch.enabled=true` 且 `rate != 1.0`；默认关闭，保持现有回归基线 |
| **落点** | `video_assembler._extract_clip`：音频 `atempo={rate}`、视频 `setpts=PTS/{rate}`；`render_clips` 所有时间戳统一 × `1/rate`；QC 增加「音画偏移 ≤ 40ms」复测 |
| **验收** | 1.2x 成片：字幕与原声仍对齐（V1 ≥ 0.7）；消音窗口核查（V5）仍通过；总时长回落在区间内 |

### 3.3 轻降噪（可选）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 去掉直播间环境噪声 |
| **收益** | 听感更干净；但会伤语音细节（尤其齿音/气声） |
| **触发条件** | 仅在 `astats` 检测到底噪 > −45dB 时启用 `afftdn`（轻档） |
| **落点** | `video_assembler` 音频链，先于 `loudnorm` |
| **验收** | A/B 对比响度与语音清晰度（V1 一致性不下降）；默认关闭 |

## 四、交付形态类

### 4.1 ⚠️ 纯画面 profile（无字幕 / 无贴纸 / 无 Hook 卡 / 无 CTA / 无品牌条）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 支持"只出画面、不带任何文字"的成片档位 |
| **收益** | 覆盖另一类发布形态（有的号主自己配字幕/避免文字压画面） |
| **触发条件** | `spec.options.render_profile: "plain"`（默认 `branded`） |
| **落点** | ① `constraints` 给 `hook_card` / `cta` 增加 `enabled`；② 字幕 `enabled` 开关（当前 `video_assembler` 的 `subtitles=` 过滤器与 `generate_ass_subtitles` 都是无条件执行）；③ **QC 必须把 6 类字幕断言降级为 SKIP（而非 PASS）**：零价格字幕、字幕违规词、字幕无繁体、banned_tokens、MarginV 安全区、V1 字幕-原声一致性 |
| **验收** | plain 成片 QC 报告里上述断言显示 SKIP 且有说明；branded 成片结果与现在完全一致（回归基线零漂移） |
| **⚠️ 风险** | QC 覆盖率实质下降，不能当"同一套流程更宽松"；违规词策略同时退化为"仅记录"（因为删字幕已无对象，声音本来就不处理） |

### 4.2 成片复制到素材目录（可选）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 交付时成片与素材同目录，方便直接取用 |
| **收益** | 省一次手动拷贝；但会污染素材目录（建议默认关闭） |
| **触发条件** | `--copy-to-source` 或 spec `options.copy_to_source=true` |
| **落点** | `scripts/generate_from_job_spec.py` 末尾 |
| **验收** | 开关关闭时行为与现在一致（零副作用） |

### 4.3 交付审核包（contact sheet）

| 项 | 内容 |
| :--- | :--- |
| **用途** | 一次交付就能人工复核"机器判不了"的那 13 项（情绪、话术-画面匹配、搭配完整等） |
| **收益** | 把人工审核从"看完整片"压缩到"看一张图 + 两段关键帧"；当前要人工拖时间轴 |
| **触发条件** | 每次成片交付 |
| **落点** | 新增 `src/tools/build_review_sheet.py`：按 `timeline.json` 每镜抽 1 帧拼 contact sheet（约 8–12 格），叠加时间码 + 分镜 id + category；输出到 `output/<pid>/review_sheet.jpg`，并在 `generation_manifest.json` 里登记 |
| **验收** | 一张图能看出每镜在讲什么；审核耗时从"看 60s"降到"扫一眼" |

## 五、流程治理类（让上面这些都"不会退化"）

### 5.1 把"作业规范"契约化为 profile

| 项 | 内容 |
| :--- | :--- |
| **用途** | 避免每次口头传达"这次要无字幕/这次语速快一点"，改为一份可版本化的配置 |
| **收益** | 可复现、可回归、可 A/B；也避免"口头要求"与代码实际行为脱节（历史上 Hook 卡文案硬编码就是这么来的） |
| **落点** | 新增 `contracts/profiles/{branded,plain,fast}.yaml`，只覆盖差异键（如 `plain` 关字幕/贴纸/CTA；`fast` 设 `time_stretch.rate=1.2`），`job_spec.options.render_profile` 引用；`constraints` 仍作默认层 |
| **验收** | 三份 profile 各跑一条成片，QC 结论符合预期；同 profile 两次运行产出差异仅在随机性（本次无随机项，应完全一致） |

### 5.2 新增约束键的"接线纪律"自动化

| 项 | 内容 |
| :--- | :--- |
| **用途** | 防止再出现"改了 yaml 但代码没读"的死键（历史踩过：贴图四键被错放在 `split_effect` 段） |
| **收益** | `audit_requirements --only-dead` 已有能力，但靠人记得跑 |
| **落点** | 把死键审计 + 需求锚点审计并入 `scripts/run_regression.py`（现在只在 quick 模式跑一部分）；PR 模板加"新增键已接线/已登记"勾选项 |
| **验收** | 故意加一个未消费的键，回归必须失败 |

### 5.3 agent 复核的"回写必达"检查

| 项 | 内容 |
| :--- | :--- |
| **用途** | 违规判定/ASR 纠错依赖 agent 回写 `*_decisions.json`；不回写就退化为正则兜底（宽松但粗） |
| **收益** | 当前只有 `review_engine=fallback` 的日志，没有阻断或提醒 |
| **落点** | `qc_auditor` 增加断言「复核回写状态」：`review_engine` 以 `fallback` 开头时记 WARN 并在报告顶部提示"本次违规判定未走 agent 复核" |
| **验收** | 不回写时 QC 报告显著提示；回写后 WARN 消失 |

### 5.4 人工判断项的抽样登记

| 项 | 内容 |
| :--- | :--- |
| **用途** | 那 13 项机器判不了的（情绪、话术-画面匹配、搭配完整性），用抽样表登记结论，形成可追踪的质量档案 |
| **收益** | 让"人工审核"也留下数据，便于后续判断哪些项值得自动化 |
| **落点** | `output/<pid>/manual_review.md`（模板化 13 项，打勾 + 备注）+ `build_content_structure_doc.py` 汇总 |
| **验收** | 连续 5 条成片有完整人工登记，能统计"哪几项长期不达标" |

## 六、实施顺序 Roadmap

| 批次 | 包含项 | 预估工作量 | 风险 | 为什么排这个顺序 |
| :--- | :--- | :--- | :--- | :--- |
| **第 1 批（本周，低风险）** | 1.1 参数占比上限、2.1 句级赘述去重、2.2 Hook 权重、1.2 主题款明确（WARN）、1.3 贵材质 ≥1 处、1.4 搭配数上限 | 各 0.5–1 天 | 极低（只加断言/调权重） | 全是"现有产物 + 阈值判定"，不改成片形态，可立即改善观感并锁定基线 |
| **第 2 批（下周）** | 4.3 交付审核包、5.1 profile 契约化、5.2 接线纪律并入回归、5.3 回写必达 | 2–3 天 | 低 | 先把"可复现 + 可审核"的底座搭好，后续改动才有对照 |
| **第 3 批（需先决策）** | 4.1 ⚠️ 纯画面 profile、3.2 ⚠️ 语速开关 | 3–5 天 | **中高**（改形态 / 全链时间轴换算） | 取决于你是否要支持这两种档位；建议二选一先做（优先纯画面，因为语速会动到所有时间戳） |
| **第 4 批（能力建设）** | 2.5 多色阶段一（颜色清单+偏好色占比）、3.1 视频端 17% 构图 | 各 3–5 天 | 中（颜色标注准确率 / 清晰度回归） | 需要新模型或新评估环节，先做阶段一验证再谈颜色转场 |
| **第 5 批（探索）** | 2.3 情绪、2.4 动态、2.6 遮挡、2.5 阶段二（颜色转场硬规则）、3.3 降噪、4.2 输出到素材目录 | 按需 | 中低 | 收益存在但边际；建议每项先做"只加权不拦截"的影子模式，观察 5 条成片再决定是否升为门禁 |

**建议的推进方式**：每批做完都跑一次 `scripts/run_regression.py --quick` + 3 条历史素材回放，把"断言数 / 误报数 / 成片指标"三项记录在案；批与批之间不要混，否则出问题无法定位是哪批引入的。

## 八、明确不建议做的（避免走回头路）

| 项 | 理由 |
| :--- | :--- |
| 引入说话人分离删"助播" | 需 pyannote 级模型，素材以主播为主，误删风险 > 收益 |
| 用 LLM 生成卖点话术 / 翻译成"用户收益" | 与本仓库"只用真实素材原声、不生成口播"的硬原则冲突，且有合规风险 |
| 把整份提示词的 34 项都做成门禁 | 其中 13 项是主观判断，硬做会造成大量误报，反而逼着人放宽阈値（历史上"违规词全库零残留"就是这么被推翻的） |
| 回退到"命中即消音+打码" | 已实测一条成片 11 处命中里多数是正常话术；现策略（仅删字幕）已定案 |
