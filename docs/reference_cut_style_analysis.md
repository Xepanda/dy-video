## 一、视频拆解总结

### 1.1 镜头/片段的挑选标准

#### 1.1.1 保留什么

| 维度 | 实测结论 | 数据 |
| :--- | :--- | :--- |
| **景别** | 主体须**完整入画**（头顶→踝可见跨度 span ≥ 0.47） | 全身为主，span 中位 0.640、区间 0.473~0.996（⚠️ span 在肢体出画时会被 MediaPipe 外推虚高，见 `external_review_response.md` §借鉴 7） |
| **展示角度** | 每段一种**不重复**的"看商品的方式" | 每段一种（并排对比 / 垂眼看 / 走动 / 站立 / 手势 / 做工 / 出行 / 持物对比 / 举衣 / 成套 / 换色快切） |
| **景别节奏** | 全身为主，细节特写做**点缀**而非主体 | 全身段占 60% 时长（31.4s/52.3s），细节段 21s |
| **画面质量** | 无黑帧、无模糊、无严重抖动 | 逐段检测，0 处异常 |
| **语音密度** | 几乎**无冷场**，句句是卖点 | 有声时长/总时长 = **96.4%** |

#### 1.1.2 舍弃什么

参考片是从**更广的素材池**（同场直播的多机位/多段素材）里挑出来的，舍弃规律清晰：

| 被舍弃的内容 | 判定依据 |
| :--- | :--- |
| **空转/寒暄**（"等一下""还没好"） | 无卖点语义、语音密度低 |
| **重复表达**（同一卖点说第二遍） | 语义重复，压缩价值为负 |
| **非商品画面**（走动、调整设备、与助理对话） | 主体不完整入画，无展示价值 |
| **价格/库存/催单话术** | 电商合规红线（直播带货片不允许出现"最后 X 件""上车链接"） |
| **高风险词**（极限词） | 违禁词库 |

> **关键取舍原则**：参考片保留的是「**商品展示价值 × 语音密度**」双高的素材，而非「时长」或「位置」。

### 1.2 段落划分逻辑与整体结构

实测叙事骨架（**与本仓库硬编码顺序相反**）：

```
hook  →  fit（比例显瘦）  →  fabric（做工细节）  →  styling（配色成套）
 4.72s     12.97+6.73s        9.80s               5.82+9.90s
```

| 阶段 | 占比 | 内容 | 观察 |
| :--- | :--- | :--- | :--- |
| 钩子 | 7% | "怎么大家都好看…肚子胯有肉的姐妹不用担心" | 直接点人群 + 给结论 |
| 比例显瘦 | 38% | "站着/这样搭才正常" | **占比最大**——半身裙的卖点重心是比例不是面料 |
| 做工细节 | 19% | 蝴蝶结包边、手工搓制 | 面料仅占 19%，远低于"展示面料"的直觉 |
| 配色成套 | 30% | 奶白上衣×卡其裙、白色成套 | 落到"怎么穿"才收尾 |

> **可复用判据**：卖点权重由**品类**决定，不是固定模板。半身裙是"比例 > 做工 > 配色"；外套/上衣类应反向。已落地为 `spec.options.funnel_order` 覆写机制（R6）。

### 1.3 镜头之间的过渡方式

**这是本轮最重要的发现，也是与本仓库分歧最大的一项。**

#### 1.3.1 实测：参考片 **10/10 全硬切**，零叠化

判据是 **α(t) 演化曲线**（把切点前后两帧 A、B 作为基向量，求中间帧的混合系数 α）：

```
硬切特征：α 在一帧内从 ~0 跳到 ~1
叠化特征：α 在若干帧上连续爬坡

参考成片 @22.31s（典型硬切）        参考成片 @29.04s
  t=22.285  α=0.010                t=28.940  α=0.005
  t=22.331  α=0.912   ← 单帧跳变    t=29.025  α=0.981   ← 单帧跳变
  t=22.376  α=0.922                t=29.110  α=0.995
```

三重交叉验证：

| 检验 | 结果 | 含义 |
| :--- | :--- | :--- |
| 逐帧差分尖峰数 | 每个切点**仅 1 帧**尖峰（跳变值 = 片内中位的 **5.1~18.6 倍**） | 无渐变帧 |
| α 单帧最大跳变 Δα | 0.815 / 0.837 / 0.434 / **0.974** / 0.977 / 0.965 / 0.818 / **0.515** / 0.872 / 0.955 | 全部为单帧切换 |
| 线性混合拟合 | 10/10 切点**零个**中间帧能被 αA+(1-α)B 解释 | 不存在叠化 |

> **复核补记（2026-11-03）**：初版用"帧差 ≥ 8×中位"作硬阈值，恰好漏掉了 49.24s
> （5.1×中位）的弱切点。**结论：参考片 10 切点 / 11 段，段长
> [4.72, 1.78, 2.85, 12.96, 6.73, 9.80, 8.89, 1.51, 4.35, 5.82, 9.90]，
> 最短 1.51s、中位 5.82s、σ=3.55、最长/最短=8.58。**
> 切点计数必须**同时**用两个判据（跳变幅度 + α 单帧跳变），只用其一会出错。

#### 1.3.2 音频侧同步为硬接，但有 2 处是 **L-Cut**（语音跨越切点连续）

切点处电平为 **−82 ~ −120 dB 数字静音**（随机位置对照仅 0.52% 命中 −60dB，**富集 29 倍**）。

但逐切点核对后，10 个切点分为两类：

| 类型 | 数量 | 切点 | 瞬时电平 | 判读 |
| :--- | :--- | :--- | :--- | :--- |
| **句末硬接** | 8 | 6.50 / 9.35 / 22.31 / 29.04 / 38.84 / 47.73 / 53.59 / 59.41 | −69 ~ −120 dB | 语音被切断，落在瞬时静音上 |
| **L-Cut（语音延展）** | 2 | **4.72** / **49.24** | **−33.0 / −33.4 dB** | 切在**句中**，但语音**连续不断**——画面跳切、声音延展 |

> ⚠️ **表述修正（2026-11-03 复核）**：初版把这些切点描述为"**数字静音缝**"，
> 暗示存在可感知的停顿。实测**静音游程仅 0.00~0.06s**——60ms 的瞬时零电平
> 在听感上是自然气口，**不构成"死寂"**。正确表述应为
> "句末处有一次 ≤60ms 的瞬时零电平接缝，听感无停顿"。

> **L-Cut** 是影视剪辑的经典手法：画面先切走，声音延后/延展继续保持，
> 或反之。参考片在 4.72s 与 49.24s 两处用了它——
> 典型场景是 29.00s：主播说"毛衣帮我准备一下"（转头拿衣服的动作被跳过），
> 画面硬切到手部蝴蝶结特写，**只保留人声作为垫音**，规避了后台杂乱。
>
> 这两处正是 11 段口径（10 切点）统计出的"句内视觉切点"（2/10 = 20%），
> 已由 R1 的 `intra_sentence_cut_max_ratio: 0.30` 覆盖。
> **即：切点机制 = 句末为主（8/10）+ L-Cut 为辅（2/10），占比上限 30%。**

> ⚠️ **上一轮的修正结论仍然有效**：这个静音是**剪辑软件切音轨留下的拼接产物**，不是选段信号。源素材侧（直播底噪 −53.4dB）在同一时刻并无静音，源侧凹陷在切点处中位 8.2dB vs 随机 9.4dB，**无富集**。
> **但它证明了一件事**：参考片在音频侧**没有做 acrossfade 交叉淡化**——acrossfade 会把切点抹平，绝不可能留下数字静音。

#### 1.3.3 无变速、无停格、无转场特效

| 项 | 实测 |
| :--- | :--- |
| 变速/停格 | 几乎完全相同的相邻帧对 **0/1511**（0.0%）→ 无升放、无重复帧 |
| 转场特效 | 零（无闪白/无推拉/无光效） |
| 运动量分布 | 段间差异大（seg02 +153%、seg04 −49%）→ 保留**真实镜头运动**，不做人工匀速 |

### 1.4 字幕与调色的处理

#### 1.4.1 字幕：**参考片无任何文字图层**（目视复核 5 帧确认）

顶部品牌条、底部字幕、挂角贴纸——**全部没有**。1s 帧背景里的"腰间 XS 62"是**场景内实物尺码牌**，不是图层。

> 这意味着：参考片只能作为「**选片与衔接**」的参考，**不能**作为字幕/包装风格的参考。本仓库的 branded 形态（字幕 + 品牌条 + 贴纸）是另一条产品线，不应被参考片带偏。

#### 1.4.2 调色：**做了统一调色**（段间变异系数极低）

| 指标 | 逐段均值 | 段间标准差 | 变异系数 | 判定 |
| :--- | :--- | :--- | :--- | :--- |
| R/G 白平衡 | 1.1345 | 0.0090 | **0.8%** | ✓ 统一 |
| B/G 白平衡 | 0.9241 | 0.0079 | **0.9%** | ✓ 统一 |
| 饱和度 | 0.2422 | 0.0086 | **3.5%** | ✓ 统一 |
| 亮度 | 0.6264 | 0.0219 | **3.5%** | ✓ 统一 |
| 对比度 | 0.2470 | 0.0192 | **7.8%** | ✓ 统一 |

> **带货场景的意义**：段间色调跳变会让观众**分不清商品真实颜色**（卡其 vs 奶白是本片的核心卖点之一）。参考片同机位同灯光，天然统一；跨机位素材则必须显式调色。

#### 1.4.3 音频：无 BGM、零音效、响度已标准化

| 项 | 实测 | 判读 |
| :--- | :--- | :--- |
| 低频/中频比 | **−21.2 dB** | 语音主导。纯 BGM 会把这个比值显著抬高 |
| 句间空隙电平 | −36.8 dB | 接近底噪 → **无音乐床铺底** |
| 动态范围（有声−空隙） | 14.9 dB | 有人声起伏，无压缩音乐 |
| 综合响度 I | **−15.3 LUFS** | 已标准化 |
| 响度动态范围 LRA | **1.5 LU** | 极窄 → 经过 loudnorm 压缩 |
| 真峰值 TP | −1.5 dBFS | 无过载 |

> 整片是**纯现场人声裸轨**，唯一的音频处理是响度标准化。

### 1.5 节奏与情绪曲线的把控

#### 1.5.1 语速与句长的分离变化（反直觉）

| 区间 | 句数 | 句长中位 | 语速 | 切点数 |
| :--- | :--- | :--- | :--- | :--- |
| 0~10s | 4 | 2.84s | 432 字/分 | **3** |
| 10~20s | 5 | 2.28s | 412 字/分 | 0 |
| 20~30s | 7 | 1.60s | 412 字/分 | 2 |
| 30~40s | 7 | 1.40s | 414 字/分 | 1 |
| 40~50s | 7 | 1.52s | 325 字/分 | 1 |
| 50~60s | 9 | 1.44s | 382 字/分 | 2 |
| 60~70s | 5 | 2.00s | 378 字/分 | 0 |

```
句长中位：  前 1/3  2.34s  →  中 1/3  1.44s  →  后 1/3  1.50s   （收紧比 0.63）
语速：      前 1/3  416 字/分 → 中 1/3 392 → 后 1/3  376          （略微变慢）
```

**关键洞察：语速在变慢，但句子在变短。** 这意味着：

- 不是"念得更快"带来的紧凑感，而是**换气更密**——更接近真人对话的呼吸节奏
- 短句 + 稍慢语速 = **可信感**（不催促、不喊麦）
- 情绪曲线是 **「钩子快 → 中段慢 → 尾段再起」**，不是全程高能

## 二、工作流改进方案

### 2.1 差距总览

| # | 环节 | 参考片实测 | 本仓库现状 | 差距等级 | 优先级 |
| :-- | :--- | :--- | :--- | :-- | :-- |
| **G1** | **过渡方式** | **10/10 纯硬切**，音频不同步淡化 | `transition_effect=fade 0.25s`（xfade+acrossfade） | 🔴 **方向相反** | **P0** |
| **G2** | **音效/BGM** | **零音效、零 BGM**、纯人声裸轨 | 硬编码混入 Sub-Bass Boom（`generate_sub_bass_boom` 无开关） | 🔴 **方向相反** | **P0** |
| **G3** | **调色一致性** | 段间变异 0.8%~7.8%（已统一调色） | **无调色、无一致性校验** | 🟠 缺失 | **P1** |
| **G4** | **节奏曲线** | 钩子快→中段慢→尾段再起；句长收紧比 0.63 | 只按时长区间约束，**无节奏/情绪曲线校验** | 🟠 缺失 | **P1** |
| **G5** | **响度** | −15.3 LUFS / LRA 1.5 / TP −1.5 | −14.0 LUFS / LRA 2.0 / TP −1.3 → 接近 | 🟢 达标 | P2 |
| **G6** | **字幕/包装** | 无（纯切片参考） | branded 全包装 | ⚪ **不适用** | — |
| **G7** | **切点位置** | 落 ASR 句末，中位偏移 0.03s | 已落地（R1，容差 0.45s） | 🟢 达标 | — |
| **G8** | **选段/时长/景别/角度** | 见 §1.1 | 已落地（R2~R4） | 🟢 达标 | — |

> **G1 与 G2 是唯二的"方向性"差距**——不是"我们做得不够"，而是"我们做的是**另一种剪辑语言**"。这必须由业务决策者拍板选边，不能默认。

### 2.2 逐项改动建议

#### 🔴 P0-1｜G1 过渡方式：从"叠化"改为"硬切"

**改动对象**：`contracts/constraints.yaml` → `slicing_rules.transition_style`（新增段）
**执行载体**：`src/tools/cut_style_rules.py::resolve_transition_style`
**接线点**：`src/core/video_assembler.py`（转场时长与音频交叉淡化改由 R7 决定，优先级高于旧 `transition_effect` 段）
**回归保护**：`tests/test_transition_chain.py`（真实 ffmpeg 跑滤镜链，秒级验证）

| 参数 | 取值 | 依据 |
| :--- | :--- | :--- |
| `mode` | `hard_cut` | 参考片 10/10 硬切 |
| `dissolve_sec` | `0.0` | 同上 |
| `audio_crossfade` | `false` | acrossfade 会抹平切点处的数字静音 |
| `insert_silence_gap` | `false` | 静音是拼接产物，不刻意制造 |

**预期效果**：切片衔接更"干净利落"，语音连贯性由 R1（切在 ASR 句末）保证，而非靠淡化掩盖——**从"用转场遮盖切点问题"转为"切点本身选得准"**。

**风险与回退**：硬切对切点精度要求更高。R1 已把容差从 2.0s 收到 0.45s，风险可控。若素材气口质量差，可临时切 `mode: dissolve, dissolve_sec: 0.15`（短叠化折中）。

**验证方式**：
```bash
python -u scripts/verify_cut_style.py --video <成片> --cuts <边界> --segments <asr.json>
# R7 判定：硬切模式要求"实测叠化 0 处"
```

#### 🔴 P0-2｜G2 音效/BGM：从"硬编码 Boom"改为"可配置且默认关闭"

**改动对象**：`contracts/constraints.yaml` → `slicing_rules.audio_style`（新增段）
**执行载体**：`src/tools/cut_style_rules.py::resolve_audio_style`
**接线点**：`src/core/video_assembler.py`

| 参数 | 取值 | 依据 |
| :--- | :--- | :--- |

## 三、附录：实测方法与判据

### 3.1 硬切 vs 叠化的判据（α(t) 演化）

```
原理：取切点前 A 帧、切点后 B 帧作基向量，对中间帧 F 求最小二乘混合系数
      α = ⟨F−A, B−A⟩ / ⟨B−A, B−A⟩
      重建误差 = |αA + (1−α)B − F|

硬切：α 在 1~2 帧内从 ~0 跳到 ~1（Δα ≈ 0.4~0.9）
叠化：α 在多帧上连续爬坡（每帧 Δα ≈ 1/(D·fps)）
```

**为什么不能用单帧最佳拟合**：窗口内的镜头运动会污染 α 值——参考片 4.72s 处 α 有爬升但残差始终 ≥32（混合模型不成立），是运动伪影而非叠化。**必须看 α 的演化形态 + 残差比**（残差比 < 0.55 且混合凹陷帧 ≥ 2 才判叠化）。

### 3.2 为什么不能用"绝对静音阈值"找气口

直播素材底噪实测 −42~−53 dB，`< −60dB` 在原始素材上命中 **0 处**。必须用**相对凹陷**（相对局部语流中位电平的下陷深度，阈值 8dB，随素材自适应）。详见 `docs/reference_cut_analysis_SSY410163.md` §2.1。

### 3.3 Boom 音效的窄带判据（一次误报修正）

**初版判据**：前 1.5s 电平峰值比全片中位高 12dB → 判"有 Boom"。
**问题**：参考成片开头就是主播在讲卖点，正常大声说话**同样满足**该条件 → 误报 FAIL。

**修正判据**（频谱窄带性）：
```
窄带比 = E(45~90Hz) / mean(E(20~45Hz), E(90~150Hz))
判有 Boom：窄带比 > 3.0
```
合成低频冲击是**窄带**的，人声基频虽低但**宽带**分布。

| 成片 | 窄带比 | 判定 |
| :--- | :--- | :--- |
| 参考成片（无 Boom） | **0.77** | ✓ 无人造低频 |
| 我们旧成片（有 Boom） | **25.30** | ✓ 检出 |

### 3.4 切点计数：用"跳变倍数"分档可消除运动伪影

高敏感度扫描（阈值 2.5×中位）会得到 **83 个候选**，其中大量是模特走动的高运动帧。
按跳变幅度分档后计数非常干净：

| 阈值 | 候选帧数 | 性质 |
| :--- | :--- | :--- |
| > 3× 中位（11.9） | 75 | 大部分是镜头运动 |
| > 5× 中位（19.8） | 10 | 含 49.24s 这个**弱真切点** |
| **> 8× 中位（31.7）** | **9** | ⚠️ 硬阈值在此**漏掉了 49.24s** |
| > 10× 中位（39.6） | 7 | 真切点中的最强几个 |

**结论（2026-11-03 复核修正）：参考片 = 10 个真切点 / 11 段。**

初版用"≥8×中位"作硬阈值，恰好把 **49.24s**（5.1×中位、Δα=0.515、α 单帧 0.000→1.000）
这个 1.51s 的"提神快切"排除在外——外部评审 `reference_video_breakdown_and_workflow_improvement.md`
记为"11 个镜头"是**正确的**。

> **复核切点数必须同时用两个判据，且阈值不能过硬**：
> ① 帧差幅度（**≥5×中位**即可作候选）+ ② α 单帧跳变（Δα>0.35）。
> 只用 Δα 会把走动帧误判为切点（83 → 45 → 10）；
> 只用帧差且阈值过严会漏掉弱切点（83 → 9 → **漏 1**）。

### 3.5 文字图层检测的两次误报

| 判据 | 结果 | 问题 |
| :--- | :--- | :--- |
| 顶部/底部高亮像素占比 | 参考片 100% "含文字" | ❌ 直播画面本身偏亮（白墙/浅色地板），阈值失灵 |
| Canny 边缘密度 | 参考片 100% "含文字" | ❌ 背景纹理（衣架、地毯纹理、窗帘）本身边缘密集 |

**最终采用目视复核**：抽 5 帧（1/15/30/45/62s）逐一判读 → 确认参考片无任何烧录文字图层。背景"腰间 XS 62"是场景内实物尺码牌。

> **教训**：图像统计判据在"高纹理直播画面"上系统性误报，**文字图层的判定应当目视或用 OCR**，不要用像素统计。

### 3.8 实施中暴露的三个潜伏缺陷（重要教训）

R7 硬切模式**首次真正执行**了装配器的 `use_trans=False` 分支，暴露两个从未被触发的缺陷：

| # | 缺陷 | 现象 | 根因 |
| :-- | :--- | :--- | :--- |
| E1 | **无转场分支丢失全部分镜** | ffmpeg 报 `Error linking filters`；成片只有第 1 段 | else 分支只接 `[0:v]`/`[0:a]`，**未串接第 2..N 段** |
| E2 | **音频链误用 `null` 滤镜** | `Media type mismatch between Parsed_null_1(video) and Parsed_anull(audio)` | `null` 是**视频**滤镜，音频链路必须用 `anull` |
| E3 | **重构残留引用未定义名** | 链构建抽成模块级函数后删了 `use_trans`，下游 meta 仍引用 → `NameError: name 'use_trans' is not defined` | 抽函数时未全局搜索该变量的所有引用点 |

**为什么潜伏这么久**：`transition_effect` 段恒为 `enabled: true` → `trans_on` 恒为 True
→ `use_trans` 恒为 True → **else 分支在历史上从未被执行过一次**。

> **教训（值得写进仓库规范）**
> 把一条配置项从"永远开启"改成"可关闭"，等于**第一次真正执行它的旁路代码**。
> 旁路代码恰恰是最缺测试覆盖的地方——切换开关本身应视为**高风险变更**，
> 必须配一条能在秒级发现问题的测试，而不是等 15 分钟的端到端流水线。
>
> 本次的处置（两道防线）：
> 1. **把链构建抽成纯函数** `build_transition_chain()`，
>    新增 `tests/test_transition_chain.py`——用 ffmpeg 生成 4 段微型素材，
>    直接执行滤镜链并断言输出时长 ≈ 各段之和（**4.00s / 4 段**；
>    若回到旧实现只会剩 1.00s）。
> 2. **新增 `tests/test_undefined_names.py`**——纯 AST 作用域分析，
>    检出"读到的名字在本作用域与所有外层可见作用域内均未绑定"的自由变量，
>    覆盖 E3 这类重构残留引用。
>
> ⚠️ 关于第 2 条：检查器本身经历了 2 版才可靠（v1 用 `ast.walk` 收集绑定 →
> 把嵌套函数的局部名混进外层 → **漏报**；v2 把子函数的 used 回流外层 →
> 子函数参数被**误报**）。最终版采用**作用域链模型**（每个作用域独立判定，
> 逐级向外查找可见性）。
> **更重要的教训：检查器必须有自验证探针**——现已在 `main()` 开头注入
> 2 个探针（函数体未定义名 / 嵌套函数未定义名），检出不了就直接 FAIL。
> 没有自验证的检查器，很容易退化成"永远绿的假检查"。
