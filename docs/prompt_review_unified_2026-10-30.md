## 0. 结论摘要（先看这四条）

1. **C 抓到了一处 A/B 的实体误判**：A 判定"福利款/性价比等合规种草词已被正确保留（不删即保留）"——**错**。实测 `INVENTORY_PATTERNS` 含 `.*福利.*`，「这个是福利款，价格特别优惠」会被整句拦截。而提示词文档明确要求保留"福利款/很划算/性价比高"。这是当前成片与业务目标的一处实质偏差，优先级最高。

## 2. 分歧点（逐条：主张 → 依据 → 事实核查 → 统一结论）

### D1｜pure_native 的优先级与工作量

| | 主张 | 依据 |
| :--- | :--- | :--- |
| **C** | 列 **P0（1–2 天）**，与 Hook 加权、fabric 收紧同批 | "在 pure_native 模式下直接旁路字幕烧录与所有 Overlay 贴图生成"，QC 加 profile 感知即可 |

**事实核查**（实测）
- `contracts/constraints.yaml:51-56` `hook_card` 段**只有** width/height/y_min/y_max/face_top_gap_px，**无 `enabled`**；`cta` 同样无。

**统一结论**：功能方向采纳 C，**优先级不采纳** —— 移出 P0，作为"需决策项"；若只做**最小可用版**（先不做逐条 SKIP，只在报告顶部声明"字幕类断言不适用"），可压到 2–3 天并进第 2 批。理由：① 这是产品形态决策（QC 覆盖率下降需你确认）；② 与"只加断言"的规则项风险等级不同，不该同批。

### D2｜语速倍率与"音高补偿"

| | 主张 | 依据 |
| :--- | :--- | :--- |
| **C** | 1.1~1.15x，"最高不超过 1.2"，并"启用音高补偿（保留真实主播音色）" | 1.15 内更自然，避免机械感 |
| **A/B** | 1.1~1.2x（文档原文"优先接近 1.2"） | 以文档为准 |

**事实核查**
- `atempo` 是**时域拉伸**，本身**不改音高**——"音高补偿"是 `asetrate`（改采样率，会变调）场景才需要。C 的表述是概念误用。
- 但 C 的**意图正确**：变速后齿音、呼吸声、口水音会被放大，需听测。

**统一结论**：倍率给三档 `1.0（默认）/ 1.15（推荐）/ 1.2（极限）`，**不实现音高补偿**（无必要），但验收必须加**主观听测**（齿音、呼吸、爆破音）。理由：技术上 atempo 已保音色；产品上 1.15 作为默认推荐档更稳，1.2 保留给"素材过硬"的场景。

### D3｜17% 构图的实现位置与验收

| | 主张 | 依据 |
| :--- | :--- | :--- |
| **C** | 落在 `video_assembler.py`，注入 `scale=w=1080*S:h=1920*S,crop=1080:1920:(iw-1080)/2:ih-1920`，`S=(1-0.17)/(1-y_head)` | 公式直接、可复现 |
| **A** | 作为"成片级构图断言"（抽帧 + Pose），触发口径"头部占比 > 阈值" | 便于复用现有 Pose 能力 |
| **B** | 抽帧评估 → 写 `plan.framing_scale` → `build_clip_filter` 消费，**必须加清晰度回归**（`post_scale_sharpness ≥ 200`） | 避免二次编码损失 |

**事实核查**
- C 的公式数学正确：底对齐放大 S 倍后，新头顶 `y' = 1-(1-y_head)·S`，令 `y'=0.17` 即得 C 式；1920×0.17 = **326.4px** ✓。
- 但需补两条边界：`S < 1` 时必须钳制为 1（否则缩成小黑框）；放大后宽度 `1080·S` 必须 ≥1080 才能裁出 1080（S≥1 时天然满足）。
- B 的清晰度门禁是现有 QC 已有能力（`post_scale_sharpness`），C 未提及。

**统一结论**：**采用 C 的公式与 ffmpeg 链**，但落点改为 **per-clip 抽取阶段**（`_extract_clip`），不是成片后处理；同时**强制保留** B 的清晰度门禁与 `S≥1` 钳制。触发口径统一为"头顶 > 0.17"单一条件（C 与 B 一致），A 的"头部占比"口径不采用（两个阈值容易互相打架）。

### D4｜`funnel.fabric.max` 到底取多少

| | 主张 | 依据 |
| :--- | :--- | :--- |
| **C** | 12~14 秒（"占比约 20%~25%"） | 与文档"4~5 分之一"对齐 |
| **A** | 12 秒 + QC「fabric 占比 ≤0.25」 | 同一目标 |
| **B** | 12 秒 + 断言 ≤0.25 | 同一目标 |

**事实核查**（按 45–65s 成片实算）
| fabric.max | 45s | 46s | 60s | 65s | 与 ≤0.25 是否兼容 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 14 | 31.1% | 30.4% | 23.3% | 21.5% | ❌ 短时长必然破线 |

**统一结论**：`fabric.max = 11`，断言 `≤0.25`。理由：三方都同意目标 20–25%，但 12/14 在短时长会与自身断言冲突（这是 A/B/C 都没算到的边界）；取 11 后无需给断言加容差，规则最干净。若你坚持 12，则断言须改为 `min(0.25, 12/总时长)`。

### D5｜"福利/性价比"是否被黑名单误杀 —— **C 正确，A/B 误判**

| | 主张 | 依据 |
| :--- | :--- | :--- |
| **C** | P0-4："微调 `INVENTORY_PATTERNS`，放行'福利款''性价比高'等合规种草词" | 担心误杀 |
| **A/B** | "✅ 已覆盖：可保留'福利款/很划算/性价比高'（黑名单只管金额/库存/链接）" | 认为黑名单不含这些词 |

**事实核查**（实测输出）
```
'这个是福利款，价格特别优惠'  → (True,  '命中库存/促销 (.*福利.*)')   ← 被拦
'性价比超高的一件'            → (False, '')                          ← 放行
'买了超级划算'                → (False, '')                          ← 放行
'这件是福利价九十九'          → (True,  '命中价格表达')               ← 被拦（价格，合理）
```
`src/tools/build_plan.py` 的 `INVENTORY_PATTERNS` 第 84 行含 `r".*福利.*"`，是**整句拦截**。

**统一结论**：**C 正确，A/B 的"已覆盖"结论作废**。修法：把 `.*福利.*` 收窄为 `.*福利价.*|.*福利秒杀.*|.*福利链接.*|.*福利到.*`（保留"福利款/福利感"），并新增**正向回归用例**：「这个是福利款，价格特别优惠」「性价比超高」必须放行；「福利价九十九」仍须拦截。这条排 P0 第一位——它直接决定"按文档剪出来的成片会不会把福利卖点全删掉"。

### D6｜多色处理：ASR 文本侧 vs 视觉标注

| | 主张 | 依据 |
| :--- | :--- | :--- |
| **C** | "基于 ASR 提取颜色关键词 + 贪心选择引入偏好色时长软约束" | 零视觉模型依赖，成本最低 |
| **A** | CLIP / 人体区域颜色直方图标注 | 文本未必提颜色（"这个色""这个"），且无法保证画面真对应 |
| **B** | 阶段一视觉标注 + 占比 QC；阶段二换色强锁 | 同上 |

**事实核查**：两者各有硬伤——纯 ASR 侧无法判断"说奶咖色但画面还是奶白"；纯视觉侧在主播说"这个色"时又没有文本引导可对齐。

**统一结论**：**双通道，不是二选一**。阶段一先落 C 的 ASR 文本侧（配额 + 引导语识别，1–2 天可上）；阶段二补视觉颜色标注做**画面校验**，只用于"引导语→下一镜"的一致性检查，不用于配额统计（配额仍以 ASR 词为准，与文档"只按达人身穿计入"的语义最接近）。

### D7｜换色段"不得跨源拼接"—— 否决 C 的这条限制

| | 主张 | 依据 |
| :--- | :--- | :--- |
| **C** | 换色引导 block 的切出点"必须与承接展示段物理相连，**不得跨源或乱序拼贴**" | 避免"声音讲奶咖、画面放奶白"的穿帮 |
| **A/B** | 无此限制；多源跨素材选段是刻意设计的核心能力（每 clip 带 `source_file`） | 禁用跨源会退化为单素材剪辑 |

**事实核查**：多源支持已在 PR #8 落地（`render_clips` 按 `clip.source_file` 取源），是当前处理"5 段素材"的基础。

**统一结论**：**否决"不得跨源"这条全局限制**，改为**局部约束**："换色引导段与其承接段必须来自**同一源文件且时间连续**（允许 ≤0.25s 转场），但成片其他镜头照常跨源"。理由：既保住"不穿帮"的业务要求，又不牺牲跨素材能力。

### D8｜Hook 加权：加性 +10 还是乘性 ×3.5

| | 主张 | 依据 |
| :--- | :--- | :--- |
| **C** | `_segment_score` 中"同时命中 `HOOK_KEYWORDS` 与 `core_words` 时 **+10.0 分**" | 简单直接 |
| **B** | 核心词命中 **×3.5**（乘性），Hook 卖点按权重累加 | 让"是否讲这款"成为必要条件 |

**统一结论**：**组合加权**——核心词用乘性（×3.0，"讲的是不是这款"是必要条件），主题款指代（这件/这条+核心词）用加性 +3.0，"强卖点词"按权重 3.0/1.5/1.0 累加；并加**单段得分封顶**（避免"堆词段"通吃）。理由：纯加性对已经命中多个钩子词的段落边际影响小（C 方案的弱点），纯乘性又容易被长句放大（B 方案的弱点）。

## 6. 结论

1. **C 的价值在于"业务语义的具体化"**（公式、px、双流派命名、颜色单元完整性），**A/B 的价值在于"可执行性与风险边界"**（可行性分层、SKIP 语义、治理机制、不建议清单）。两者不是对立，而是"用什么做"与"该不该现在做"的分工。
2. **交叉比对最大的产出是 U1**：C 揪出了一条被 A/B 判成"已覆盖"的实体缺陷——`.*福利.*` 会把"福利款"整句删掉，与提示词"保留福利感"直接冲突。这条应排本迭代第一位。
3. **所有分歧的收敛方式都不靠投票，而靠实测**：D4 靠比例计算（11 而非 12）、D5 靠跑正则（C 对）、D1 靠查配置键（无 `enabled`）、D3 靠公式验证（C 对但缺门禁）。建议后续评审都沿用"先跑一条命令再下结论"的做法。
4. **仍需你决策的只有三项**（U9 纯画面档位、U10 语速、U11 时长下限），它们都是"产品形态"，不是工程判断——这也是为什么 A/B 把它们从 P0/P1 里拆出来的原因。
5. **不要再扩范围**：34 项自检里 13 项永远需要人判，硬做门禁只会导致误报堆积、阈值被反复放宽（违规词"全库零残留"就是这么被推翻的）。这些项请走 U18 的抽样登记 + U15 的审核包。
